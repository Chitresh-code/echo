Using Echo

Tool approvals

An agent asks before it does something that changes its workspace or reaches outside it. You allow or deny each call from the chat, or switch the workspace to Yolo and let it work without asking.

Two modes

  • Ask before tools, the default: commands, file writes and edits, web requests, background processes and every MCP server's tools wait for your answer. Reading files, using skills and notes, keeping its plan and starting subagents never ask.
  • Yolo: every call runs without asking. The settings label under the message box shows yolo while it is on.

Switch with the /approvals command in the message box, or in Name and purpose in the workspace menu. Switching to Yolo while a call waits lets that call run.

Answer a call

A waiting call shows as a card in the reply with the tool, which subagent asked if one did, the server's own notes about the tool for MCP tools, and exactly what the call will run with. Pick:

  • Allow to run this call.
  • Allow for this chat to run this call and every later call of the same tool in this chat without asking. A new chat asks again.
  • Deny to refuse it. The agent is told you denied it and asks you what to do instead of trying again.

The card then says how it was answered. The reply keeps running on the server while it waits, so you can close the page and answer later from the same chat in any tab.

A call waits 10 minutes. With no answer by then it does not run and the agent is told so; the waiting time does not count against the reply's time limit. Stopping the reply refuses every call still waiting.

What the server says about a tool

An MCP server can label its tools, for example as read only or destructive. The card shows these labels as the server's claim, and Echo still asks: a server can label a tool however it likes.
