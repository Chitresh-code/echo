Running Echo

Data and backups

Everything Echo keeps lives in two Docker volumes on the machine it runs on. Nothing is copied anywhere else, so backing them up is up to you.

The two volumes

  • echo_sandbox-data holds each agent's workspace: its files, its skills in .agent/skills/ and the history of its changes, which is a git repository. It also holds the recent output of the agent's processes and each workspace's network address.
  • echo_api-data holds Echo's database (people, agents and their encrypted model keys), each chat's conversation and each agent's notes.

An agent's skills and its notes are in different volumes, so back up both together.

How long it lasts

Volumes do not expire. They survive restarts, rebuilds and docker compose down, and are deleted only by docker compose down -v or docker volume rm.

An agent's workspace history is a local git repository. It is not pushed to GitHub or anywhere else.

Back up

Stop Echo first so nothing changes during the copy, then archive each volume into the current folder:

docker compose stop
docker run --rm -v echo_sandbox-data:/data -v "$PWD":/backup alpine tar czf /backup/sandbox-data.tgz -C /data .
docker run --rm -v echo_api-data:/data -v "$PWD":/backup alpine tar czf /backup/api-data.tgz -C /data .
docker compose start

Keep the ECHO_SECRET_KEY from .env with the backup. Without it the stored model keys cannot be read, and everyone has to add theirs again.

Restore

With Echo stopped, unpack each archive into its volume:

docker compose stop
docker run --rm -v echo_sandbox-data:/data -v "$PWD":/backup alpine sh -c 'rm -rf /data/* /data/.[!.]* ; tar xzf /backup/sandbox-data.tgz -C /data'
docker run --rm -v echo_api-data:/data -v "$PWD":/backup alpine sh -c 'rm -rf /data/* /data/.[!.]* ; tar xzf /backup/api-data.tgz -C /data'
docker compose start

Restoring replaces everything in the volumes with the backup. Anything done since the backup is lost.
