Agents

An agent is something you create to do one job for you, such as "triage new bug reports" or "keep the release notes current". You show it the job in a chat and correct it, and what it learns stays with that agent. Each agent has its own workspace: a folder with its own git repository where it keeps its files, notes and the workflows it learns. Everything that happens in the workspace runs inside that agent's jail, so nothing in one agent can reach another.

Your agents belong to you: nobody else signed in to Echo can see or use them.

Your agents

The Agents page, the first page after you sign in, lists your agents with their name, their job and when you last used them, most recently used first. Search filters the list by name or job.

  • New agent asks for a name (up to 80 characters) and the job it does (up to 500), then opens the agent.
  • The pencil on an agent changes its name or job.

Agents cannot be deleted yet.

An agent's page

Opening an agent shows three panels: the files on the left, the editor in the middle and the chat on the right. On a narrow window they stack.

The left panel has three tabs: Files, Skills and Notes.

  • Skills: what the agent has learned to do, one row per skill with its name and when the agent uses it. Click one to open its SKILL.md in the editor, where you can change it like any file. A red mark means the agent cannot load that skill, a yellow one that it loads but breaks the format; hover for the reason. The agent is told about both at the start of its next turn so it can fix them.
  • Notes: the short notes the agent keeps from each chat, newest first. The bin button, then Forget, deletes a note for good, so the agent no longer remembers it.
  • Explorer (the Files tab): every file and folder in the workspace. Files changed since the last commit carry git's letter: M modified, U new, D deleted. The count of changed files shows next to the agent's name. The new-file button creates a file; refresh reloads the list, which also happens after every chat turn.
  • Editor: open files in tabs, edit them and save with the Save button or Ctrl+S (Cmd+S on a Mac). A tab with unsaved edits is marked, and the browser warns before you leave with unsaved edits. Files that are not text show as "Binary file, not shown".
  • Diff: for a changed file, Diff shows the last commit next to the file as it is now. A new file is compared with an empty one.

If the agent changes a file you have open with unsaved edits, your text stays and the editor says the file changed on disk, with a button to reload it.

From the API

Everything on these screens is also in the API reference. The examples assume $ECHO holds your session cookie, as on the Signing in page.

curl -b "$ECHO" -X POST http://localhost:8000/api/agents \
  -H 'content-type: application/json' \
  -d '{"name": "Release notes", "job": "Keep CHANGELOG.md current from merged work"}'
  • GET /api/agents lists your agents, most recently used first; GET /api/agents/{id} returns one, and PATCH /api/agents/{id} with name or job changes it.
  • GET /api/agents/{id}/tree lists every file and folder except .git, at most 5000 entries.
  • GET /api/agents/{id}/file?path=src/app.py reads a file. Text comes back as is; a file that is not UTF-8 text comes back base64 encoded, and the answer says which.
  • PUT /api/agents/{id}/file with {"path": "src/app.py", "content": "..."} saves a text file and creates any folders it needs.
  • GET /api/agents/{id}/git/status lists the files changed since the last commit, and GET /api/agents/{id}/git/file?path=... returns a file as it was in the last commit and as it is now.

Paths are relative to the workspace, such as src/app.py. A path that starts with / or uses .. is refused. Files larger than 5 MB cannot be read or saved this way.

When something goes wrong

Every error has a code you can act on, such as file_not_found, invalid_path, file_too_large or agent_not_found (also the answer for someone else's agent), and a request_id to quote when you report a problem.
