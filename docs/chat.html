Chat with the agent

You give an agent a task in a chat, and it does the work in its workspace: it reads and edits files, runs commands, installs packages and commits with git. Everything it runs happens inside the agent's jail, which can reach the internet but not your machine or your network. Your model provider key stays with the Echo server and never reaches the jail.

The chat panel

The chat is the right-hand panel on an agent's page. Below the message box:

  • The model button picks one of your keys and one of its models. Without a key, it links to the Credentials page instead.
  • Effort sets how hard the model thinks (see below). Keys for an OpenAI-compatible service take only auto.

Your browser remembers the model and effort you chose. Enter sends, Shift+Enter starts a new line. The agent's reply appears as it is written, each tool it uses shows as a row with the tool's name, and when the turn ends you see the tokens it used and how long it took. The explorer then reloads, since the agent may have changed files.

The stop button stops watching the turn, but the agent finishes it on the server, and its result shows in the files. The new-chat button starts a fresh conversation. Reloading the page keeps the same chat, so the agent still remembers it, but earlier messages are not shown again: chats are not stored for viewing yet.

Links in the agent's replies open in a new tab, and images from other sites are shown as links and never loaded, since a page or file the agent read could otherwise make your browser send data to another site.

From the API

The examples assume Echo is at http://localhost:8000, $ECHO holds your session cookie (see Signing in), you have an agent id, and a key id from GET /api/credentials.

Start a chat

curl -b "$ECHO" -X POST http://localhost:8000/api/agents/{id}/chats

The answer holds the chat's id. An agent can have many chats. Each one keeps its own conversation, so a later message in the same chat can refer to earlier ones.

Send a message

curl -b "$ECHO" -N -X POST http://localhost:8000/api/agents/{id}/chats/{chat}/turns \
  -H 'content-type: application/json' \
  -d '{"prompt": "Create a small Vite site that says hello, build it and commit it",
       "credential_id": "your key id", "model": "claude-sonnet-5-5"}'

credential_id is the id of one of your keys, and model one of the model ids from GET /api/credentials/{id}/models. Each message names its key and model again, so you can move a chat to another model or provider at any message. The new model sees the whole conversation, but not the earlier model's hidden reasoning, which no other model can read. A key id that is not one of yours answers credential_not_found.

To choose how hard the model thinks, add "effort": one of auto, off, minimal, low, medium, high, xhigh or max. Higher levels help with hard tasks but are slower and cost more; off turns reasoning off where the model allows it. Without it the message uses auto, the level recommended for the model. Models take different levels, and one a model does not take answers effort_not_supported with the levels it does take. Keys for an OpenAI-compatible service take only auto.

The agent's reply streams back as it works, as server-sent events:

  • text: a piece of the agent's reply.
  • tool: the agent started using a tool, such as shell, read, write or edit.
  • done: the turn is over. Its usage holds the tokens the turn used on your model: inputTokens, outputTokens, cacheReadInputTokens and cacheWriteInputTokens. Summaries of web pages and the agent's notes are made by the provider's small model on the same key and are not included.
  • error: the turn stopped early. It has a code and, when the server failed, a request_id to quote when you report it.

A model id the key cannot use, or a key the provider has since revoked, makes the turn fail with turn_failed once it starts; check the list of models for the key.

Afterwards, look at what changed with the file and git endpoints on the Agents page.

What the agent can do

The agent runs shell commands, reads, writes and edits files, fetches web pages, uses the provider's own web search where the provider has one, loads its skills and searches its notes. Everything except web search runs in the agent's jail. Web pages, files and command output are treated as information, not as instructions: if a file or page tells the agent to do something you did not ask for, it does not do it and tells you. When a task changes files, it commits them, and it ends each turn with what it changed, how it checked it and what it could not do.

To keep cost down, summaries of fetched pages and the agent's notes are made by the provider's small model (Claude Haiku 5.5, gpt-6-luna or Gemini 3.5 Flash Lite) on the same key. Keys for an OpenAI-compatible service use the chosen model for this too.

What the agent keeps

The agent is told its name and its job at the start of every turn, so a change to either applies from your next message. It stays on that job: it still helps with something outside it, but says so. Without a job, it learns the job from what you ask and suggests you write it down.

When you correct the agent or show it how you want something done, it saves that as a skill: a SKILL.md with the steps, and any scripts it needs, in .agent/skills/<name>/ in the workspace. It tells you in one line what it learned and where it saved it, and uses its skills on later tasks. A new skill is available from your next message.

Put an AGENTS.md file at the root of the agent's workspace with conventions for the workspace itself, such as how to run things or where files go. The agent reads it at the start of every turn and keeps it up to date. It also keeps short notes across chats.

Limits

  • One message at a time per chat. Sending another while the agent is still working gets the chat_busy error. Wait for done, or start a second chat.
  • A turn stops after 30 minutes (ECHO_TURN_TIMEOUT). Each command the agent runs stops after 2 minutes (ECHO_COMMAND_TIMEOUT) unless the agent asks for longer, up to 30 minutes (ECHO_COMMAND_TIMEOUT_MAX). The agent is told both limits.
  • Stopping curl stops the turn and the command that was running. The stop button in the browser does not: the turn finishes on the server.
  • The agent cannot open a server it starts, such as a dev server, because the jail cannot reach localhost. It can build and test, and anything that runs to completion works.
