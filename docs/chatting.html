Using Echo

Chatting

You give the agent work in the chat that fills each workspace's page. It does the work in that workspace: it reads and edits files, runs commands, installs packages and keeps a history of its changes.

Send a message

Type / at the start of a line in the message box to see the commands. Keep typing to narrow the list, move with ↑ and ↓, pick with Enter or Tab, and press Esc to close the menu and keep what you typed.

  • /model lists the models of each of your keys, grouped by key, with a tick on the one in use. Type part of a name to find it, for example /model mini. Without a key, it offers to open Credentials.
  • /effort sets how hard the model thinks. auto uses the level recommended for the model and off skips extra thinking. Higher levels help with hard tasks but are slower and cost more. Keys for an OpenAI-compatible service take only auto.

The model and effort the next message uses show in small text in the corner of the message box. Click it to choose from the same lists with a search field, which is handy on a phone. A message that is only a command is never sent, while a line that starts with a slash but is not a command, such as /etc/hosts is missing, is sent as written.

Enter sends and Shift+Enter starts a new line. In a code block Enter adds a line, and Ctrl+Enter (⌘+Enter on a Mac) sends from anywhere. Your browser remembers the model and effort you chose. You can switch to another model or provider at any message, and the new model sees the whole conversation so far.

Format a message

The message box formats as you type, using Markdown: **bold**, *italic*, `code`, three backticks and a space for a code block, - or 1. at the start of a line for a list and > for a quote. Web addresses that start with http://, https:// or www. become links; file names such as hello.py stay text. Pasted Markdown keeps its formatting, and text pasted from a web page keeps only that formatting, never images or scripts. The message is sent, and shown in the chat, as Markdown.

A message can be up to 100,000 characters; a counter shows near the limit.

Unsent messages

What you type and have not sent is kept for each workspace, and for the home screen, while the browser tab stays open, so you can go to Credentials or another workspace and come back to it. Signing out clears it. If a message cannot be sent, such as when you are at the workspace limit or a reply is still running, it stays in the box with the reason above it.

Follow along

The reply appears as it is written. Each tool the agent uses shows as a row with the tool's name, such as shell, read, edit or write, and what it acted on: the command, the file, the web address or the skill it loaded. A row turns red when the call failed. The output of commands is not shown; the agent tells you what matters. When the reply is done you see the tokens it used and how long it took, and the files panel reloads, since the agent may have changed files.

When the reply added, changed or removed a skill, a Learned line names it. Teaching your agent explains it.

Plans and subagents

For a task with several steps the agent keeps a plan, shown as a checklist in its reply. Steps tick off as it works, and the step in progress has an arrow.

The agent can hand a self-contained part of a task, such as searching the code or reviewing a change, to a subagent: a helper with the same tools and workspace that starts without this conversation. Each subagent shows as a block with its task and the tools it runs, and a tick or a cross when it ends; select the task line to fold it. Up to two run at once, a subagent cannot start subagents of its own, and the agent continues once their answers are back. Subagents run on the same model and key, and their tokens are included in the reply's total.

Stop, and start fresh

  • Stop stops the reply and the command it is running. A command a subagent is running finishes first. What the agent already changed stays in its files.
  • New chat, in the workspace header, starts a fresh conversation. The agent keeps its skills, notes and files across chats; only the conversation starts over.

Reloading the page keeps the same chat, so the agent still remembers it, but earlier messages are not shown again.

A reply runs only while its page is open. If you go to another page or close the tab while the agent is working, Echo asks first, and leaving stops the reply. What it already changed stays in its files.

What the agent can do

It runs shell commands, reads, writes and edits files, fetches web pages, uses the provider's web search where there is one, loads its skills and searches its notes. When a task changes files it saves them to the workspace's history, and it ends each reply with what it changed, how it checked it and anything it could not do.

It stays on its job. It still helps with something outside it, but says so.

Web pages, files and command output are information to the agent, never instructions. If something it reads tells it to do something you did not ask for, it does not do it, and tells you.

Links in the agent's replies open in a new tab. Images from other sites show as links and are never loaded, so a page the agent read cannot make your browser send data elsewhere.

Servers and previews

Each agent's workspace has its own network, so a server the agent starts in one command answers the next one at localhost, and no other agent can reach it. The agent starts servers and watchers, such as npm run dev, as processes that keep running after the command that started them. Ask it to start one, and to say which port it listens on.

Open the files panel from the workspace header and choose Preview above the editor to see them:

  • Each process with its command and whether it is running or has exited. Output shows what it printed, and Stop stops it.
  • The ports listening in the workspace. Select one to show its page under the list. Reload shows changes, and Open in a new tab opens the page on its own.

The page runs on an address of its own, never on Echo's, so a page the agent made cannot act as you in Echo. Only you can open your agent's previews. An open preview keeps working for 8 hours, and stops at once if the agent is deleted. If Preview says previews are not set up, whoever runs Echo has not turned them on; processes and their output still show.

A process stops when it exits, when the agent or you stop it, after 2 hours, or when Echo restarts. An agent can run up to 3 at once.

Pages update when you press Reload, not on their own: the live reload of dev servers such as Vite does not connect through the preview.

Limits

  • One message at a time per chat, and up to 2 replies running at once across all your chats, unless whoever runs Echo set another number.
  • A reply stops after 30 minutes, and each command the agent runs stops after 2 minutes unless the agent asks for longer, up to 30 minutes.
  • To keep cost down, summaries of web pages and the agent's notes are made by the provider's small model on the same key, and are not counted in the tokens shown.
