Getting started

Echo runs as two containers on one machine: the app you talk to, and a sandbox where the agent's work runs. People sign in with their Microsoft work account, and each person adds their own model provider key.

What you need

  • Docker with Compose, on Linux or Docker Desktop (macOS or Windows).
  • Permission to run privileged containers. The sandbox needs it to create a jail for each agent.
  • A Microsoft Entra tenant (your organization's Microsoft 365 or Azure directory), and the right to register an app in it.

You do not need a model provider key to install Echo. Each person adds their own after signing in, on the Keys page.

Register Echo in Microsoft Entra

In the Microsoft Entra admin center, open App registrations and choose New registration:

  • Name: anything, such as Echo.
  • Supported account types: accounts in this organizational directory only (single tenant).
  • Redirect URI: platform Web, address http://localhost:8000/api/auth/callback. If Echo will be opened at another address, use that address followed by /api/auth/callback.

After registering, note the Application (client) ID and the Directory (tenant) ID on the app's overview. Then, under Certificates & secrets, add a client secret and copy its Value (not its Secret ID). It is shown only once.

Anyone in your tenant can sign in. To allow only some people, open the app under Enterprise applications, set Assignment required to Yes, and add those people or their groups under Users and groups.

Install

From the Echo folder, create your settings file:

cp .env.example .env

Open .env and fill in:

ECHO_PUBLIC_URL=http://localhost:8000
ECHO_MS_TENANT_ID=the Directory (tenant) ID
ECHO_MS_CLIENT_ID=the Application (client) ID
ECHO_MS_CLIENT_SECRET=the client secret's Value
ECHO_SECRET_KEY=a key you generate, see below

ECHO_SECRET_KEY encrypts the provider keys people store in Echo. Make one with:

python3 -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'

or, without the cryptography package, openssl rand -base64 32 | tr '+/' '-_'. Keep it safe and do not change it: with a different key, every stored provider key becomes unreadable and has to be added again.

Then build and start Echo:

docker compose up --build

Echo will not start if a setting is missing or malformed, and it tells you which one, without printing secret values. Settings are read only when Echo starts, so restart it after changing .env:

docker compose restart api

Check it is running

Echo listens only on your own machine. Open http://localhost:8000 and you should see Echo's sign-in page; http://localhost:8000/api/health answers "status": "ok". Then sign in.

Always open Echo at exactly the address in ECHO_PUBLIC_URL. Opened at another address, such as http://127.0.0.1:8000 when the setting says localhost, sign-in cannot return to it and changes are refused with bad_origin.

If port 8000 is already taken, set another one in .env, and change ECHO_PUBLIC_URL and the redirect URI in Entra to match:

ECHO_PORT=8010
ECHO_PUBLIC_URL=http://localhost:8010

Echo listens only on your own machine for now. Do not expose it to a network: the sandbox does not yet have the limits needed before other people use it.

Where your data is kept

Everything Echo keeps lives in two Docker volumes on this machine. echo_sandbox-data holds each agent's workspace: its files, its skills in .agent/skills/ and its git history. echo_api-data holds Echo's database (people, agents and their encrypted keys), each chat's conversation and each agent's notes. Volumes do not expire: they survive restarts, rebuilds and docker compose down, and are deleted only by docker compose down -v or docker volume rm.

An agent's workspace is a git repository, but it is not pushed anywhere. Nothing is copied off this machine, so back up both volumes if the agents' work matters, for example with docker run --rm -v echo_sandbox-data:/data -v "$PWD":/backup alpine tar czf /backup/sandbox-data.tgz -C /data . and the same for echo_api-data, with Echo stopped.

If something goes wrong

Every error Echo returns includes a request_id. Search the logs for it to see what happened:

docker compose logs api | grep <request_id>
