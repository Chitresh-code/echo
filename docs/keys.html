Using Echo

Model keys

Your agents run on a model from a provider you pay for, using your own key. You add a key once, then pick it and one of its models in the chat.

Which providers work

  • Anthropic: a key from the Anthropic Console.
  • OpenAI: a key from the OpenAI platform.
  • Google: a Gemini API key from Google AI Studio.
  • OpenAI-compatible: any service with an OpenAI-compatible API, such as OpenRouter or a hosted inference service, at its https address.

Your keys are yours alone: nobody else signed in to Echo can see, use or delete them. Echo stores them encrypted, never shows them again after you add them, and never lets them into an agent's workspace.

The Credentials page

Credentials in the top bar lists your keys with their provider, the last four characters of the key and when you added it.

  • Add a key at the bottom: pick the provider, give the key a label you will recognize and paste it. Echo asks the provider for its models first, and saves the key only if that works.
  • Models on a key shows the models it can use.
  • The bin deletes a key after asking. To replace a key, add the new one and delete the old one.

OpenAI-compatible services

For a compatible service, also give its address: the part before /chat/completions, such as https://openrouter.ai/api/v1. The address must start with https://. Echo refuses addresses that are not on the public internet, such as your own machine or your office network, so a model you run yourself, such as Ollama, cannot be used.

Some services, such as company gateways, answer chat requests but cannot list their models. For those, type the model ids to use in the Models field, separated by commas, up to 50. Echo then checks the key with one short chat request to the first model, which costs a fraction of a cent, so put a chat model first.

If a key is refused

The provider refused the key
Check you copied all of it and that it is still active.
The address is not allowed
The service's address is on a private network or your own machine, or is not an https address.
The provider did not answer as expected
Try again later. If it keeps happening, tell whoever runs Echo when it happened: the details are in Echo's log. A service that cannot list its models also answers this way: add its model ids as above.
The first model is not available
The service does not serve the first model in your list. Check its id.
A key stopped working
If a key you added earlier can no longer be read, Echo's encryption key was changed by whoever runs it. Add the key again.
