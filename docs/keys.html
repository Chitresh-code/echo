Model provider keys

The agent runs on a model from a provider you pay for, using your own API key. You add a key once, and then pick it and one of its models each time you send the agent a message. Echo works with:

  • anthropic: a key from the Anthropic Console.
  • openai: a key from the OpenAI platform.
  • google: a Gemini API key from Google AI Studio.
  • openai_compatible: any service with an OpenAI-compatible API, such as OpenRouter or a hosted inference service, at its https address.

Your keys are yours: nobody else signed in to Echo can see, use or delete them. The examples assume you set $ECHO as on the Signing in page.

Add a key

curl -b "$ECHO" -X POST http://localhost:8000/api/credentials \
  -H 'content-type: application/json' \
  -d '{"provider": "anthropic", "label": "Work", "api_key": "your key"}'

For a compatible service, add its address, the part before /chat/completions:

  -d '{"provider": "openai_compatible", "label": "OpenRouter", "api_key": "your key", "base_url": "https://openrouter.ai/api/v1"}'

Echo checks the key by asking the provider for its models, and stores it only if that works. The answer holds the key's id, which you use when you chat. The key itself is stored encrypted and is never shown again; answers show only its last four characters as key_hint, or nothing for a short key.

See your keys and their models

  • GET /api/credentials lists your keys, newest first.
  • GET /api/credentials/{id}/models lists the models the key can use, asked live from the provider. Use one of these id values as the model when you chat.
  • DELETE /api/credentials/{id} removes a key. To replace a key, add the new one and delete the old one.

Compatible services

Because Echo calls the address you give it, the address is checked first. It must start with https:// and have no user name, password, ? or # in it. When Echo connects, it refuses any address that is not on the public internet: your own machine (localhost), your home or office network, and cloud metadata addresses. A model you run yourself on your machine or network, such as Ollama, cannot be used for that reason.

When something goes wrong

  • invalid_key: the provider refused the key. Check you copied all of it and that it is active.
  • endpoint_not_allowed: the service's address is on a private network or your own machine.
  • invalid_base_url: the address is not an https address, or has parts Echo does not accept. Only openai_compatible keys take a base_url.
  • provider_error: the provider did not answer as expected. Try again later; the request_id finds the details in Echo's log.
  • credential_not_found: there is no key of yours with that id.
  • credential_unreadable: Echo can no longer decrypt the key, because the server's secret was changed. Add the key again.
