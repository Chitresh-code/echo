Running Echo

Install and set up

For whoever runs Echo. It runs as two containers on one machine: the app people use, and a sandbox where agents' work runs. People sign in with their Microsoft work account and each adds their own model key, so you do not need one to install it.

What you need

  • Docker with Compose, on Linux or Docker Desktop (macOS or Windows).
  • Permission to run privileged containers. The sandbox needs it to create a jail for each agent.
  • A Microsoft Entra tenant (your organization's Microsoft 365 or Azure directory), and the right to register an app in it.

Register Echo in Microsoft Entra

In the Microsoft Entra admin center, open App registrations and choose New registration:

  • Name: anything, such as Echo.
  • Supported account types: accounts in this organizational directory only (single tenant).
  • Redirect URI: platform Web, address http://localhost:8000/api/auth/callback. If Echo will be opened at another address, use that address followed by /api/auth/callback.

After registering, note the Application (client) ID and the Directory (tenant) ID on the app's overview. Then, under Certificates & secrets, add a client secret and copy its Value (not its Secret ID). It is shown only once.

Anyone in your tenant can sign in. To allow only some people, open the app under Enterprise applications, set Assignment required to Yes, and add those people or their groups under Users and groups. Someone removed later cannot sign in again, but a session they already have stays valid until it ends, up to 7 days later.

Fill in the settings

From the Echo folder, create the settings file:

cp .env.example .env

Open .env and fill in:

ECHO_PUBLIC_URL=http://localhost:8000
ECHO_MS_TENANT_ID=the Directory (tenant) ID
ECHO_MS_CLIENT_ID=the Application (client) ID
ECHO_MS_CLIENT_SECRET=the client secret's Value
ECHO_SECRET_KEY=a key you generate, see below

ECHO_SECRET_KEY encrypts the model keys people store in Echo. Make one with:

python3 -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'

or, without the cryptography package, openssl rand -base64 32 | tr '+/' '-_'.

Keep the secret key safe and do not change it. With a different key, every stored model key becomes unreadable and everyone has to add theirs again.

Optional limits, also in .env: ECHO_AGENT_DISK_MB is each agent's storage in MB (2048), ECHO_MAX_AGENTS the workspaces each person may have (50), and ECHO_MAX_RUNNING_TURNS the replies each person may have running at once (2). Each message sent from the home screen starts a workspace, so people collect them quickly. With the defaults, one person can use at most 100 GB, though most workspaces stay far below their limit; lower either setting to bound it tighter.

Turn on previews

Previews show the pages of servers an agent starts, in tabs beside the agent's files. They are off until you set where they are served. Each agent and port gets its own address under that name, so a page an agent made never runs on Echo's address. On your own machine, add to .env:

ECHO_PREVIEW_URL=http://preview.localhost:8000

Browsers send every name ending in .localhost to your own machine, so this needs no other setup. Use the same port as ECHO_PUBLIC_URL. Restart the api afterwards.

Anywhere else the address must be https, and you need a wildcard DNS name, such as *.echo-preview.example.net, pointing at Echo, with a wildcard certificate for it. Use a different domain from Echo's own if you can. Echo refuses to start if the preview name is the same as Echo's, sits under or above it, or has a path.

Start Echo

docker compose up --build

Echo will not start if a setting is missing or malformed, and it says which one without printing secret values. Settings are read only when Echo starts, so restart it after changing .env:

docker compose restart api

Check it is running

Open http://localhost:8000 and you should see the sign-in page, and http://localhost:8000/api/health answers "status": "ok". Then sign in.

Always open Echo at exactly the address in ECHO_PUBLIC_URL. Opened at another address, such as http://127.0.0.1:8000 when the setting says localhost, sign-in cannot return to it and changes are refused with bad_origin.

If port 8000 is taken, set another in .env, and change ECHO_PUBLIC_URL and the redirect URI in Entra to match:

ECHO_PORT=8010
ECHO_PUBLIC_URL=http://localhost:8010

Echo listens only on your own machine for now. Do not expose it to a network: the sandbox does not yet have the limits needed before other people use it.

If something goes wrong

Every error Echo returns from its API includes a request_id. Search the logs for it to see what happened:

docker compose logs api | grep <request_id>

When someone cannot sign in, the log also has the reason Microsoft gave.
