Using the API

Everything in the app is also in the API. This page shows the common calls with curl. The API reference lists every endpoint, with a form to try each one as you.

Your session

The API uses the same sign-in as the app. Your session is a cookie named echo_session. Copy its value from your browser's developer tools (Application or Storage, then Cookies, then the Echo address) and set it once in your shell:

export ECHO='echo_session=the value'
curl -b "$ECHO" http://localhost:8000/api/auth/me

GET /api/auth/me shows who you are signed in as and POST /api/auth/logout signs you out everywhere. A session lasts 7 days. Without one, every call answers 401 with the code not_signed_in.

Anyone with this value can act as you until the session ends, so do not paste it anywhere shared. Signing out ends it.

Every answer is JSON. Every error has a code you can act on and a request_id to quote when you report a problem.

Model keys

curl -b "$ECHO" -X POST http://localhost:8000/api/credentials \
  -H 'content-type: application/json' \
  -d '{"provider": "anthropic", "label": "Work", "api_key": "your key"}'

provider is anthropic, openai, google or openai_compatible. For a compatible service, add its address, the part before /chat/completions:

  -d '{"provider": "openai_compatible", "label": "OpenRouter", "api_key": "your key", "base_url": "https://openrouter.ai/api/v1"}'

For a service that cannot list its models, also give models, up to 50, with a chat model first:

  -d '{"provider": "openai_compatible", "label": "Gateway", "api_key": "your key",
       "base_url": "https://gateway.example.com/v1", "models": ["gpt-5.4-mini"]}'

The answer holds the key's id, which you use when you chat. The key itself is never shown again; answers show only its last four characters as key_hint, or nothing for a short key.

  • GET /api/credentials lists your keys, newest first.
  • GET /api/credentials/{id}/models lists the models the key can use, asked live from the provider, or the list you gave. Use one of these id values as the model when you chat.
  • DELETE /api/credentials/{id} removes a key.
invalid_key
The provider refused the key.
endpoint_not_allowed
The service's address is on a private network or your own machine.
invalid_base_url
The address is not https, has a user name, password, ? or #, or was given for a provider other than openai_compatible.
provider_error
The provider did not answer as expected, or a compatible service cannot list its models (give models).
model_not_available
The service does not serve the first model in models.
models_not_supported
Only openai_compatible keys take models.
credential_not_found
There is no key of yours with that id.
credential_unreadable
The server's secret was changed, so the key cannot be decrypted. Add it again.

Agents

curl -b "$ECHO" -X POST http://localhost:8000/api/agents \
  -H 'content-type: application/json' \
  -d '{"name": "Release notes", "job": "Keep CHANGELOG.md current from merged work"}'

name is 1 to 80 characters and job up to 500. Both are optional: without a name the workspace is called "New workspace" until its first message names it, which the turn reports as a title event.

  • GET /api/agents lists your agents, most recently used first.
  • GET /api/agents/{id} returns one, and PATCH /api/agents/{id} with name, job or approval_mode changes it. approval_mode is ask (the default: tool calls that change something or reach outside the workspace wait for an answer) or yolo (nothing waits), and can also be given when the agent is created.
  • GET /api/agents/{id}/mcp-servers lists the MCP servers the agent uses, and PUT with {"server_ids": [...]} replaces the set, at most 10 (too_many_mcp_servers). An id that is not one of your servers answers mcp_server_not_found.
  • GET /api/agents/{id}/skills lists its skills with their description and status: ok, warning or skipped, with the problem.
  • GET /api/agents/{id}/notes lists its notes, newest first, and DELETE /api/agents/{id}/notes/{name} forgets one. A missing note answers note_not_found.
  • GET /api/agents/{id}/usage returns used_bytes and limit_bytes for its files and home.
  • DELETE /api/agents/{id} deletes the agent with its files, skills, notes and chats, for good.

Someone else's agent answers agent_not_found, the same as one that does not exist.

agent_limit_reached
You have as many workspaces as allowed (50 by default). Delete one first.
agent_busy
A delete while one of the agent's chats is answering. Wait for it to end.
disk_quota_exceeded
Saving a file to an agent over its storage limit (507).

Files and changes

  • GET /api/agents/{id}/tree lists every file and folder except .git, at most 5000 entries.
  • GET /api/agents/{id}/file?path=src/app.py reads a file. Text comes back as is; a file that is not UTF-8 text comes back base64 encoded, and the answer says which.
  • PUT /api/agents/{id}/file with {"path": "src/app.py", "content": "..."} saves a text file and creates any folders it needs.
  • POST /api/agents/{id}/folders with {"path": "src/lib"} makes a folder and any folders above it.
  • POST /api/agents/{id}/files uploads files as a multipart form: files (one or more), folder (empty for the top of the workspace) and overwrite. Up to 20 files and 25 MB at a time, 5 MB each. Without overwrite=true, names that are already there answer files_exist and nothing is written.
  • GET /api/agents/{id}/git/status lists the files changed since the last commit, and GET /api/agents/{id}/git/file?path=... returns a file as it was in the last commit and as it is now.

Paths are relative to the workspace. A path that starts with / or uses .. answers invalid_path. Files over 5 MB answer file_too_large, and a missing one file_not_found.

Processes and previews

The agent starts servers and watchers as processes. You can watch and stop them, but not start them.

  • GET /api/agents/{id}/processes returns processes, each with name, command, cwd, status (running or exited), exit_code and started_at, and ports, the TCP ports listening in the agent's workspace.
  • GET /api/agents/{id}/processes/{name}/logs?tail=200 returns the last lines a process printed, 1 to 1000.
  • DELETE /api/agents/{id}/processes/{name} stops it.
  • POST /api/agents/{id}/preview with {"port": 3000} returns a url that shows that port's page. Open it in a browser within a minute; it gives that browser access to this one agent and port for 8 hours.
process_not_found
The agent has no process with that name.
preview_off
Previews are not set up on this Echo (ECHO_PREVIEW_URL is not set).

Terminals

A terminal is a shell in the agent's sandbox, in the workspace folder. It keeps running when nobody is connected, until it exits, is ended, has been unwatched for 30 minutes or has run for 8 hours.

  • POST /api/agents/{id}/terminals with {"cols": 80, "rows": 24} starts one and returns its id, started_at and attached, the number of connections watching it.
  • GET /api/agents/{id}/terminals lists the running ones.
  • DELETE /api/agents/{id}/terminals/{terminal_id} ends one.
  • A WebSocket at /api/agents/{id}/terminals/{terminal_id} connects to it, signed in with the session cookie and opened from Echo's own address. It first sends the recent output, then the output as it comes, as binary frames. Send text frames {"type": "input", "data": "ls\r"} to type and {"type": "resize", "cols": 120, "rows": 30} when the screen changes size. It closes with 1000 when the shell exits, 4404 when the terminal is not there and 4401 when you are not signed in.
too_many_terminals
The workspace has 4 terminals open (409), or the sandbox has as many as it can run (429).
terminal_not_found
The terminal has ended.

MCP servers

Your MCP servers, which agents use for tools from outside their workspace. A remote server is reached at an https address:

curl -b "$ECHO" -X POST http://localhost:8000/api/mcp-servers \
  -H 'content-type: application/json' \
  -d '{"name": "sentry", "kind": "remote", "url": "https://mcp.sentry.dev/mcp",
       "auth": "headers", "headers": {"Authorization": "Bearer your token"}}'

A local server is a command run in each agent's workspace that uses it:

curl -b "$ECHO" -X POST http://localhost:8000/api/mcp-servers \
  -H 'content-type: application/json' \
  -d '{"name": "everything", "kind": "local", "command": "npx",
       "args": ["-y", "@modelcontextprotocol/server-everything"], "env": {}}'

name is a lowercase letter, then up to 19 lowercase letters, digits or underscores, unique among your servers; it prefixes the server's tools, as in sentry_search_issues. auth is none, headers or oauth, the last with an optional client_id and client_secret from the provider. Header and environment values are stored encrypted and only their names come back, in header_names and env_names. A remote server with no sign-in or with headers is connected when added and returned with its tools; a local one lists its tools on the first turn that uses it.

  • GET /api/mcp-servers lists your servers with their status: ok, needs_auth, needs_scope or tools_changed.
  • PATCH /api/mcp-servers/{id} with {"headers": {...}} or {"env": {...}} replaces the whole set.
  • DELETE /api/mcp-servers/{id} deletes it, and agents stop using it.
  • POST /api/mcp-servers/{id}/oauth returns {authorize_url} to open in the browser. After the user approves, the provider returns to /api/mcp/oauth/callback, which goes on to /mcp?connected={id} or /mcp?error={code}. The address works once, within 10 minutes, for the user who asked for it.
  • POST /api/mcp-servers/{id}/tools/review with {"hash"} accepts a server's changed tools: pending_tools lists them and pending_hash is the hash to send. A hash that is no longer the one waiting answers tools_moved_on.
mcp_server_limit_reached
You have 20 servers. Delete one first.
mcp_server_name_taken
You already have a server with that name.
endpoint_not_allowed
The address, or one the server sent Echo to (its sign-in metadata, registration or token address), is not https or is not on the public internet.
mcp_auth_failed
The server refused the headers.
oauth_no_metadata
From /oauth: the server publishes no OAuth metadata, so Echo has no sign-in or token address to use. Add it with headers instead.
oauth_unsupported
From /oauth: the provider's sign-in does not offer PKCE with S256, or its sign-in address is not https.
mcp_server_error
The server could not be reached or did not answer as an MCP server. The details are in Echo's log.

Usage

GET /api/usage?start=2026-11-01&end=2026-11-30&tz=Europe/Berlin reports your usage over the whole days from start to end (at most 366) in the IANA time zone tz (UTC when left out). An unknown zone answers usage_timezone_invalid and a reversed or too long range usage_range_invalid. Money is in integer millionths of a US dollar (cost_micros), estimated from public list prices.

  • totals: cost_micros, the four token counts, turns, and unpriced_tokens, the tokens of models with no known price, which are left out of the cost.
  • days: one {date, cost_micros, tokens} per day of the range, zero on days without usage.
  • workspaces, models and keys: {id, name, provider, cost_micros, tokens, turns, unpriced_tokens}, most expensive first. name is null for a deleted workspace or key, and a model's id is provider/model.
  • prices: {source, fetched}, where the price list came from and when.
  • since: when your first counted usage was recorded, or null.

Chats

Start a chat, then send messages to it. Each chat keeps its own conversation, and an agent can have many.

curl -b "$ECHO" -X POST http://localhost:8000/api/agents/{id}/chats
curl -b "$ECHO" -N -X POST http://localhost:8000/api/agents/{id}/chats/{chat}/turns \
  -H 'content-type: application/json' \
  -d '{"prompt": "Create a small Vite site that says hello, build it and commit it",
       "credential_id": "your key id", "model": "claude-sonnet-5-5"}'

A turn runs on the server to its end whether or not anyone reads its stream, so closing the connection does not stop it.

credential_id is one of your keys and model one of its model ids. Each message names them again, so you can move a chat to another model or provider at any message. The new model sees the whole conversation, but not the earlier model's hidden reasoning.

Add "effort" to choose how hard the model thinks: auto (the default, the level recommended for the model), off, minimal, low, medium, high, xhigh or max. A level the model does not take answers effort_not_supported with the levels it does take. Keys for an OpenAI-compatible service take only auto.

The reply stream

The reply streams back as server-sent events:

turn
{id}: always first, the turn's id, for following or stopping it.
text
A piece of the agent's reply.
tool
The agent started using a tool, such as shell, read, write or edit.
tool_detail
{id, detail}: what a tool call acted on (its command, path, address, task or skill), at most 200 characters, once its input is complete.
tool_result
{id, ok}: whether a tool call succeeded. Its output is not sent. For subagent this is only the acknowledgement that it started; delegate_done says how it ended.
skill
{id, name}: the skill a skills tool call loaded. It follows that tool's event.
todos
{items}: the agent's whole plan each time it changes, at most 30 items of {text, status}, where status is pending, in_progress or completed.
delegate
{id, task}: a subagent started for the subagent tool call id.
delegate_tool, delegate_tool_result
{delegate, id, name, detail} and {delegate, id, ok}: a subagent's tool calls, with delegate naming its subagent call.
delegate_done
{id, ok}: the subagent for that call ended, and whether it finished.
approval_needed
{id, tool, server, hints, subagent, input}: a tool call waits for an answer, in Ask mode. server and hints (the server's own annotations, not checked) are set for MCP tools, subagent is the task of the subagent that asked, and input_cut is true when input was cut short for display. Answer with POST /api/agents/{id}/approvals/{approval id} and {"decision"}: allow, deny or always (allow that tool for the rest of the chat). An id that is not waiting answers approval_not_found. A call waits 10 minutes.
approval_done
{id, decision}: how a waiting call was answered: allow, always, deny or timeout.
mcp_unavailable
{server, reason, detail}: one of the agent's MCP servers is left out of this turn, and why. detail is the end of a local server's error output when it exited, and is never shown to the model.
title
{name}: the name the workspace was given from your first message, sent once in the first turn of a workspace created without a name. It can arrive after done, so read the stream to its end. Until it comes, the workspace is named after the start of the message.
done
The turn is over. usage holds the tokens it used so far on every model, subagents and the small model's side work included (inputTokens, outputTokens, cacheReadInputTokens, cacheWriteInputTokens), with costMicros, the estimated cost in millionths of a US dollar (null when no call had a known price), and unpriced, true when some calls had none. Side work that ends after done is added to the turn's stored usage, which is final. learned lists the skills the turn added, changed or removed.
stopped
The turn was stopped on request.
error
The turn stopped early. It has a code and, when the server failed, a request_id.
  • One message at a time per chat: another one while the agent works answers chat_busy. More than 2 replies running at once across your chats (by default) answers 429 too_many_turns.
  • A key id that is not yours answers credential_not_found. A model the key cannot use, or a key the provider has revoked, fails with turn_failed once the turn starts.
  • A turn stops after 30 minutes (ECHO_TURN_TIMEOUT). Each command stops after 2 minutes (ECHO_COMMAND_TIMEOUT) unless the agent asks for longer, up to 30 (ECHO_COMMAND_TIMEOUT_MAX).

Stored chats

  • GET /api/agents/{id}/chats lists the agent's chats, most recently used first, 50 at a time, each with id, title, created_at, updated_at and running. When more is true, ask again with ?before= the last chat's id.
  • GET /api/agents/{id}/chats/{chat} gives the chat with its latest 30 turns, oldest first. Each turn has its prompt, model, effort, status (running, done, failed, stopped or interrupted when Echo restarted during it), usage, times and the events its stream sent. truncated means the turn was too long to keep in full (over 5,000 events or 2 MB). For earlier turns, pass ?before= the first turn's id while more is true.
  • GET /api/agents/{id}/chats/{chat}/turns/{turn}/events streams the turn's events from its start: a running turn is followed to its end, an ended one is replayed.
  • POST /api/agents/{id}/chats/{chat}/turns/{turn}/stop stops a running turn and the command it is running; its stream ends with stopped. stopping is false when the turn had already ended.
  • DELETE /api/agents/{id}/chats/{chat} deletes the chat and the agent's memory of it, for good. It answers chat_busy while a turn runs and chat_not_found for a chat that does not exist.
