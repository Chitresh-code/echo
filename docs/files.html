Using Echo

Files and changes

Everything an agent makes lives in its workspace. You can read and edit any file, and see exactly what the agent changed.

The Files tab

The Files tab in the files panel, opened from the workspace header, lists every file and folder in the workspace. A file changed since the last saved version of the workspace carries a letter:

  • M modified
  • U new
  • D deleted

The number of changed files shows in the workspace header. Refresh reloads the list, which also happens after every reply.

Add files and folders

New file and New folder at the top of the Files tab, or on a folder's row when you point at it, open a name box in the tree, in the folder you are in. It tells you as you type when a name is taken or cannot be used. A name with slashes, such as src/lib/util.ts, makes the folders on the way. Enter makes it and Escape cancels. A new file opens in the editor.

To bring in files from your computer, use Upload, or drop files onto the Files tab or onto a folder in it. You can add up to 20 files and 25 MB at a time, 5 MB each. If a file with the same name is already there, Echo asks before replacing it. Folders cannot be uploaded; upload the files inside them instead.

Edit a file

Click a file to open it in a tab in the editor. Pages of running servers open in tabs beside your files; see Servers and previews. Save with the Save button or Ctrl+S (Cmd+S on a Mac). A tab with unsaved edits is marked, and the browser warns you before you leave with unsaved edits. Files that are not text show as "Binary file, not shown".

If the agent changes a file you have open with unsaved edits, your text stays and the editor tells you the file changed, with a button to reload it.

See what changed

For a changed file, Diff shows the last saved version next to the file as it is now. A new file is compared with an empty one. This is the quickest way to check the agent's work before you rely on it.

The agent saves a version of the workspace whenever it finishes a task that changed files, so the letters clear after each finished task. The letters you see are work in progress, including your own edits.

Terminal

The Terminal button in the files panel header, or Ctrl+`, opens a shell under the editor. It runs in the same sandbox as the agent, in the workspace folder, with the same tools and the same network, so what you run there sees what the agent made and the agent sees what you change. Drag the top edge of the panel to make it taller or shorter.

Use + to open another shell, up to 4 per workspace, each in its own tab. A shell keeps running when you close the page or lose the connection: open the terminal again and it reconnects and shows its recent output. A shell nobody is watching ends after 30 minutes, any shell ends after 8 hours, and all shells end when Echo restarts. Closing a terminal's tab ends its shell.

The Processes tab beside the terminals lists the servers and watchers the agent started; see Servers and previews.

Storage limit

Each agent has room for 2 GB, unless whoever runs Echo set another limit. That covers its files and the tools it installs for itself. The bottom of the Files tab shows how much it uses, in yellow once it passes 90%.

When an agent goes over its limit, it can still read and delete files but cannot write any, and neither can you from the editor. The agent is told this on its next command, so you can ask it to clean up: build output, node_modules and downloaded packages are usually the biggest. A single command can take an agent past the limit before it is stopped.

To free all of a workspace's space at once, delete it with Delete in its ⋯ menu, in the sidebar or the workspace header. That removes its files, skills, notes and chats for good.

Good to know

  • Files larger than 5 MB cannot be opened or saved in the editor.
  • The list shows up to 5000 files and folders.
